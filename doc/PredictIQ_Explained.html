📥 Phase 1
Data Load + Label Creation
Read CSV, drop the hidden column, and compute the target variable: "will it fail within N hours?"
rw = pd.read_csv(dp) # ── Drop hidden health score ────────── rw.drop(columns=["_health_hidden"]) # ── Compute TTF (Time To Failure) ───── fail_t = rw["t_sec"].where(rw["fail_event"]) rw["next_fail_t"] = fail_t.groupby(rw["machineID"]).bfill() rw["ttf_sec"] = rw["next_fail_t"] - rw["t_sec"] # ── Create binary target ────────────── rw["fail_within_N"] = (rw["ttf_sec"] <= N_hrs*3600).astype(int)
🔑
KEY TRICK — bfill(): For each row, look forward in time to find the next failure timestamp. Subtract current time → get "seconds until next failure" (TTF). If TTF ≤ 3600s (1 hour) → label = 1.

rwDataFrameRaw data (345,600 rows)
fail_tSeriest_sec only at failure rows, NaN otherwise
next_fail_tSeriesNext upcoming failure timestamp (bfill)
ttf_secSeriesSeconds until next failure (regression target)

🔧 Phase 2
Feature Engineering (Part A)
Drop ID columns, create 3 domain-derived features from raw sensors to help the model.
dc = ["machineID","t_sec","fail_event", "next_fail_t","ttf_sec","fail_within_N"] x = rw.drop(columns=dc) # ── 3 Derived Features ─────────────── x["power_per_rpm"] = x["power"] / x["rotation"] x["temp_x_vib"] = x["temp"] * x["vib"] x["maint_load"] = x["hours_since_maint"] * x["power"] y_target = rw["fail_within_N"] # classification y_ttf = rw["ttf_sec"] # regression grp = rw["machineID"] # for splitting
power_per_rpm
power ÷ rotation
Power efficiency per revolution. Rises when machine works harder for same speed (wear signal).
temp_x_vib
temp × vib
Thermal stress index. Both go up near failure, so product amplifies the failure signal.
maint_load
hours_since_maint × power
How hard machine worked since last service. High = more wear accumulated.
✂️ Phase 3
Train/Test Split by Machine
Split data so that entire machines go to either train OR test — never both. This prevents data leakage.
gss = GroupShuffleSplit( n_splits=1, test_size=.25, random_state=Seed ) tr_idx, te_idx = next(gss.split(x, y_target, grp)) x_train = x.iloc[tr_idx] # 75% machines x_test = x.iloc[te_idx] # 25% machines y_train = y_target.iloc[tr_idx] y_test = y_target.iloc[te_idx] ttf_train = y_ttf.iloc[tr_idx] ttf_test = y_ttf.iloc[te_idx]
🚫
Why NOT random split? A random 75/25 would put rows from the SAME machine in both train and test. The model would memorise that machine's patterns → fake high accuracy → fail in real world. GroupShuffleSplit fixes this.

📏 Phase 4
Baseline — Logistic Regression
Simple first model to establish a baseline score before using heavy-duty models.
# Standardise so all features are on same scale ss = StandardScaler() x_train_sd = ss.fit_transform(x_train) x_test_sd = ss.transform(x_test) # Baseline classifier lgr = LogisticRegression( class_weight="balanced", # handles imbalance max_iter=1000, random_state=Seed ) lgr.fit(x_train_sd, y_train) pred = lgr.predict(x_test_sd) prob = lgr.predict_proba(x_test_sd)[:, 1]
✅
Why class_weight="balanced"? Only ~0.025% rows are failures. Without balancing, the model just predicts "Normal" for everything and gets 99.97% accuracy — useless! Balanced weights make the model pay more attention to rare failure rows.
🚀 Phase 5
XGBoost Classifier
Gradient boosting — much more powerful than logistic regression. Handles non-linear patterns and interactions.
# Weight for imbalance: majority/minority ratio spos_wt = (y_train==0).sum() / (y_train==1).sum() xgb = XGBClassifier( n_estimators = 300, # 300 trees max_depth = 4, # tree depth learning_rate = 0.05, # step size scale_pos_weight = spos_wt, # imbalance weight eval_metric = "aucpr" # area under PR curve ) xgb.fit(x_train, y_train) xgb_ypred = xgb.predict(x_test) xgb_yprob = xgb.predict_proba(x_test)[:, 1]

📊 Phase 7
Evaluation + Cost-based Threshold
Default threshold is 0.5 but that's not optimal here. We sweep thresholds to minimise the total business cost.
# Sweep thresholds from 0.05 to 0.95 bth, bc = 0.5, np.inf for t in np.arange(0.05, 0.95, 0.01): pat = (xgb_yprob >= t).astype(int) fn = ((pat==0) & (y_test==1)).sum() # missed failures fp = ((pat==1) & (y_test==0)).sum() # false alarms c = fn*cost_fn + fp*cost_fp # total cost if c < bc: bc, bth = c, t
💰
Business logic: Missing a real failure (FN) costs 10× more than a false alarm (FP). So we lower the threshold below 0.5 — this catches more real failures at the cost of more false alarms. That's the right trade-off here.
VariableMeaning
bthBest threshold (optimal cost)
bcBest (lowest) total cost
fnFalse Negatives — missed failures (expensive!)
fpFalse Positives — false alarms (cheap)

Phase B — Advanced Features (Phases 9–15)
Rolling Features + Regression + Uncertainty Bounds

Phase B adds time-series trends, predicts exact time-to-failure (not just binary yes/no), and gives a confidence interval around each prediction.

📈 Phase 9
Rolling Time-Series Features
Raw sensor values miss trends. A rising temperature over 5 minutes is more alarming than a single high reading.
rc = ["temp","vib","pressure","rotation","power"] for c in rc: g = rw.groupby("machineID")[c] # Rolling mean (smooth average) x[f"{c}_rmean"] = g.transform( lambda s: s.rolling(30).mean()) # Rolling std (is it fluctuating?) x[f"{c}_rstd"] = g.transform( lambda s: s.rolling(30).std()) # Trend over 30 readings (going up/down?) x[f"{c}_trend"] = g.transform( lambda s: s.diff(30))
📉
3 new features per sensor × 5 sensors = 15 new columns. rmean smooths noise, rstd catches instability, trend shows if sensor is rising or falling. This is how the model learns "temperature is climbing fast → failure soon."

🎯 Phase 13
Quantile Regression — Uncertainty Bounds
Instead of one prediction, gives a confidence interval: "failure in 30–90 minutes" instead of just "60 minutes."
# 10th percentile (pessimistic / earliest) q_lo = XGBRegressor( objective="reg:quantileerror", quantile_alpha=0.1) # 90th percentile (optimistic / latest) q_hi = XGBRegressor( objective="reg:quantileerror", quantile_alpha=0.9) # Alert system: use pessimistic bound alerted = lo_pred <= alert_h # sounds alarm early actual_soon = ttf_test <= alert_h caught = (alerted & actual_soon).sum()

🚀 Phase 15
predict() — Live Prediction Wrapper
The final user-facing function. Give it one sensor reading row, get back a complete failure risk assessment.
def predict(row_df): # Time to failure (seconds) ttf_pred = np.clip(xgb_reg.predict(row_df), 0, None)[0] # Pessimistic and optimistic bounds lo = np.clip(q_lo.predict(row_df), 0, None)[0] hi = np.clip(q_hi.predict(row_df), 0, None)[0] # Failure probability fail_prob = float(xgb_b.predict_proba(row_df)[:, 1][0]) fail_soon = "Yes" if fail_prob >= bth else "No" return { "fails_within_N": fail_soon, "Probability" : round(fail_prob*100, 1), "time_left" : sec2hrs(ttf_pred), "Range" : f"{sec2hrs(lo)}–{sec2hrs(hi)}" }

📁 Raw Data (factory_sim.csv)
345,600 rows of sensor readings from 20 machines, taken every 10 seconds. Each row has temp, vib, pressure, rotation, power + maintenance history.
🏷️ Label Creation (Phase 1)
Use bfill() to find the next failure for every row. Compute TTF. Label = 1 if failure within 1 hour.
🔧 Feature Engineering (Phases 2 + 9)
Add 3 domain features (Phase A) + 15 rolling features (Phase B) = richer picture of machine behaviour over time.
✂️ Safe Split (Phase 3)
GroupShuffleSplit ensures machine IDs never appear in both train and test. 15 machines train, 5 machines test.
🤖 Train 6+ Models (Phases 4–6, 10–11, 13)
Logistic Regression baseline → XGBoost → 3 Random Forest variants → Ridge regressor → XGBoost regressor → 2 Quantile regressors.
📊 Evaluate + Optimise (Phases 7, 12)
Confusion matrix, PR curve, ROC-AUC. Sweep thresholds 0.05→0.95 to find minimum business cost. XGBoost wins.
🔍 Explain (Phases 8, 14)
SHAP values reveal which sensors drive each prediction. Top features: temp trends, vibration, power_per_rpm.
🚀 Deploy (Phase 15)
predict(row_df) → instant answer: will it fail? when? how confident? what's the uncertainty range?
