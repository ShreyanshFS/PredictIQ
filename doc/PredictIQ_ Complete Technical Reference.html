PredictIQ: Complete Technical Reference (v2)

Predictive maintenance from sensor data | Author: Shreyansh Dwivedi | single file main.py, top-to-bottom

Goal: given a machine's sensor reading, output (1) fails within N hours? Yes/No, (2) failure probability %, (3) time left as hh:mm:ss, (4) an 80% time range.

New in v2: two output modes chosen at start, Operator (clean machine prediction) and Analyst (full technical report and all graphs), so non-technical users are no longer buried in technical output.

How it works (Config block)

Analyst=(mode=="2")
Show_plot=Analyst
def log(*a,**k):
    if Analyst: print(*a,**k)
def show():
    mp.show() if Show_plot else mp.close()
  • mode: the user's menu choice, "1" or "2". The input loop rejects anything else and asks again.
  • Analyst: True/False flag, True only for mode 2.
  • log(): behaves like print() but prints only in Analyst mode. Used for all technical output (Phases 0 to 14 and the takeaways).
  • show(): shows the plot in Analyst mode, closes it silently in Operator mode. It replaces mp.show() at the 6 plot points. The mp.show() inside show() itself stays, otherwise the function would call itself forever.
  • print() kept (visible in both modes): the first line "Model Started", the mode menu, the invalid-choice message, the Phase 15 prediction output, and "Model Stopped". The decoration line ------><------- also uses print, so it shows in both modes.

  1. N_hrs (prediction horizon in hours), 2. mode (1 or 2).

5. Phase 1: Data and Labels

  1. pd.read_csv, sort by machineID, t_sec, reset_index(drop=True). Variable rw.
  2. Drop _health_hidden (hidden ground truth, would leak the answer).
  3. Logs: shape, columns, machine count, unique time steps, total missing values.
  4. Time to failure: fail_t = t_sec.where(fail_event), then groupby(machineID).bfill() gives next_fail_t. ttf_sec = next_fail_t - t_sec.
  5. Censored rows (ttf_sec NaN, after a machine's last failure) are dropped. Logs rows dropped and kept.
  6. Label: fail_within_N = (ttf_sec <= N_hrs*3600).astype(int). Logs the positive rate and TTF stats (hours).

6. Phase 1.5: Cleaning

  • sensor_cols = temp, vib, pressure, rotation, power. Logs missing count before and after.
  • groupby(machineID).transform(ffill().bfill()): last known value forward, then leading gaps backward. Per machine, so nothing leaks across machines.

7. Phase 2: Features and Targets

  • Dropped (dc): machineID, t_sec, fail_event, next_fail_t, ttf_sec, fail_within_N. x = sensors + hours_since_maint (+ any other remaining CSV columns).
  • Derived: power_per_rpm = power/rotation, temp_x_vib = temp*vib, maint_load = hours_since_maint*power.
  • Targets: y_target (0/1), y_ttf (seconds), grp (machine ID).

8. Phase 3: Split

GroupShuffleSplit(n_splits=1, test_size=0.25, random_state=Seed) grouped by machine. Logs shapes, machine IDs per set, machine overlap (empty set), positive rates, mean TTF. Reason: one machine's consecutive readings are near-identical, so a row split would leak.

9. Phase A: Classification

Phase 4, Logistic Regression (baseline). StandardScaler fit on train only. LogisticRegression(class_weight="balanced", max_iter=1000, random_state=Seed), default L2, C=1. Logs classification report (Normal/Failure), ROC-AUC, PR-AUC, chance-level PR-AUC (= test positive rate).

Phase 5, XGBoost Classifier. spos_wt = negatives/positives. XGBClassifier(n_estimators=300, max_depth=4, learning_rate=0.05, scale_pos_weight=spos_wt, eval_metric="aucpr", random_state=42) on unscaled data. Logs report, ROC-AUC, PR-AUC (print labels say "Accuracy" and "Precision" but show ROC-AUC and PR-AUC), and Logistic PR-AUC for comparison.

Phase 6, Imbalance study. All use RandomForestClassifier(n_estimators=100, random_state=Seed, n_jobs=-1):

Variant Method
Plain No handling
Balanced class_weight="balanced"
SMOTE SMOTE(random_state=Seed) on train only, default k_neighbors=5, minority raised to 1:1

Logs class counts before and after SMOTE, then a report and PR-AUC x 100 per variant.

Phase 7, Evaluation.

  • Plot 1: confusion matrix, XGBoost, threshold 0.5, cmap="Blues".
  • Plot 2: Precision-Recall curve (orange).
  • Cost sweep: np.arange(0.05, 0.95, 0.01), cost = FN*10 + FP*1, best threshold saved as bth (starts at 0.5). Logs bth, its cost and the 0.5 cost. Tuned on test data, slightly optimistic.

Phase 8, SHAP (classifier). TreeExplainer(xgb). Plot 3: bar of mean |SHAP|. Plot 4: beeswarm summary.

10. Phase B: Time Left, Range and Alerts

Phase 9, Rolling features (per machine, per sensor, window 30, 15 new columns):

Column Formula NaN
{c}_rmean rolling mean, min_periods=1 none
{c}_rstd rolling std, min_periods=1 fillna(0)
{c}_trend diff(30) fillna(0)

Backward-looking only. Train and test re-sliced with tr_idx/te_idx.

Phase 10, Ridge. Ridge(alpha=1.0, random_state=Seed) on unscaled features, predictions clipped at 0. RMSE and MAE in hours, plus test TTF mean and std.

Phase 11, XGBoost. xgb_reg = XGBRegressor(n_estimators=300, max_depth=5, learning_rate=0.05, random_state=Seed), clipped at 0, RMSE and MAE vs Ridge. xgb_b = same settings as Phase 5 with the rolling features. Logs PR-AUC for Phase B vs Phase A.

Phase 12, Results table. Ridge vs XGBoost RMSE and MAE (hours), holdout machine IDs, and (1 - rmse_b/rmse)*100 % lower RMSE.

Phase 13, Uncertainty and alerts. q_lo and q_hi: XGBRegressor(n_estimators=300, max_depth=5, learning_rate=0.05, objective="reg:quantileerror", quantile_alpha=0.1 / 0.9, random_state=Seed), clipped at 0. Coverage = share of true TTF inside [lo, hi] (target about 80%). Alert: lo_pred <= N_hrs*3600. Logs caught / total and false alarms.

Phase 14, SHAP (regressor). TreeExplainer(xgb_reg). Plot 5: bar. Plot 6: beeswarm.

Phase 15, predict().

sec2hrs(s) clamps at 0 and returns HH:MM:SS. predict(row_df) returns fails_within_N, Probability (%), time_left, Range. Demo: x_test.sample(3, random_state=Seed). Analyst mode then logs the takeaways (RMSE vs Ridge, PR-AUC snapshot vs rolling, coverage, alerts). Ends with print("Model Stopped") and raise SystemExit.

14. Metrics

ROC-AUC, PR-AUC (average_precision_score), classification report, confusion matrix, total cost (FN x 10 + FP x 1), RMSE, MAE (hours), interval coverage, alerts caught / false alarms. PR-AUC is the main metric because failures are rare.

15. Limitations and Code Notes

  • Simulated data (proof of concept).
  • bth is tuned on the test set and comes from Classifier A but is used with Classifier B.
  • Print labels "Accuracy"/"Precision" in Phases 5 and 6 actually show ROC-AUC and PR-AUC.
  • dc is reused as a name in Phase 7; Step_sec, train_test_split, roc_curve, seaborn are unused.
  • Ridge runs on unscaled features; its random_state is inactive.
  • Operator mode still trains every model (RF, SMOTE, SHAP), so it waits as long as Analyst mode. Skipping those in Operator mode is a possible speed-up.
  • The Operator currently sees 3 random test rows, not a chosen machine (see planned next step).

16. Run

Put factory_sim_hard.csv in Data/, install the libraries, run python main.py, enter N in hours, then choose mode 1 or 2.
